# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## What this is

VidGrab — a PySide6 (Qt) desktop app that downloads YouTube videos/playlists/channels as MP4/MP3 via yt-dlp (optionally flipped / trimmed / sped up) and joins clips in an editor-style Studio (music medley, or video montage with positioned burned-in subtitles and background music) via ffmpeg. Pages: Download, Studio, Settings. UI languages: English and Traditional Chinese only. Shipped as a single-file PyInstaller binary for Windows and Linux with ffmpeg/ffprobe embedded.

## Commands

```bash
make setup      # create .venv + install requirements.txt (one-time)
make ffmpeg     # fetch the pinned ffmpeg/ffprobe (ffmpeg/pin.json) into ffmpeg/linux
make run        # python -m vidgrab
make lint       # ruff check vidgrab tests scripts   (CI runs `ruff check .`)
make test       # SMOKE_GUI=1 QT_QPA_PLATFORM=offscreen pytest -v
make build      # write_version_info.py + PyInstaller VidGrab.spec → dist/VidGrab
make icon       # regenerate assets/icon.{png,ico} + docs/icon.png from vidgrab/icon.py
```

Single test: `.venv/bin/python -m pytest tests/test_downloader.py::test_name -v`

On WSLg, creating the first `QAudioOutput` can stall ~70 s (the PulseAudio socket); run tests / driver scripts with `PULSE_SERVER=unix:/nonexistent` (fails fast and stays silent).

Test gating via environment variables:
- `SMOKE_GUI=1` (+ `QT_QPA_PLATFORM=offscreen`) — enables `tests/test_gui_smoke.py`; skipped otherwise.
- `VIDGRAB_INTEGRATION=1` — enables `tests/test_integration.py` (real YouTube downloads + ffmpeg). Skips itself when YouTube bot-blocks the IP. CI runs it only on pushes to main.
- ffmpeg-dependent tests in `test_downloader.py` skip when ffmpeg/ffprobe aren't on PATH.

## Architecture

- `vidgrab/downloader.py` — all non-GUI logic, Qt-free and unit-testable. Public entry points: `probe()` (info card metadata), `download()`, `download_both()` (MP4+MP3 single pass), `download_playlist()`, `derive_mp3()`. `process_local_file()` has no UI caller any more; it stays as the tested entry point for the shared `_trim` post-processing. Each takes `on_progress`, `on_log` callbacks and a `translate` function so user-facing messages are localized without importing Qt or i18n state.
- `vidgrab/studio.py` — Qt-free Studio engine: `compose_audio()` / `compose_video()` build **one** ffmpeg `-filter_complex` graph (per-clip `-ss/-t` inputs → normalize → `concat` or chained `acrossfade` → optional `subtitles` → optional `amix` music bed) and parse `-progress pipe:1` for real progress. `build_*_command()` are pure and unit-tested. Subtitles are written as **ASS** (`format_ass`) with `PlayRes` = output size. Cues with `x`/`y` get `\\an5\\pos()`, and sizes are given against libass's 288-line reference (`subtitle_scale`). They are burned in by running ffmpeg with `cwd` set to a temp dir that holds `subs.ass` and a `fonts/` copy of the bundled Noto Sans CJK TC. That avoids the subtitles filter's Windows path-escaping problems and fontconfig lookups.
- `vidgrab/captions.py` — Qt-free auto captions: `transcribe(sources, models_dir, …)` takes `CaptionSource`s (a clip's source start / end, speed and montage offset, from `StudioPage.caption_sources()`) and returns `SubtitleCue`s in montage time. **Three engines**, tried in order `speech_engines(gpu, models_dir)` (NVIDIA `cuda` → Intel `openvino` → `cpu`; NVIDIA goes after OpenVINO while its 1.3 GB of CUDA libraries are still to be downloaded), each falling back to the next on any exception except `DownloadCancelled`: `_FasterWhisper` (CTranslate2 float16 on CUDA, int8 on the CPU with `gpu.speech_threads()`) and `_OpenVino` (OpenVINO GenAI `WhisperPipeline` on the Intel GPU; segment-level times only, so `chunk_words()` spreads each segment over its characters / words; 60 s slices cut at quiet points by `audio_slices()` give progress; silent slices and `is_hallucination()` text are skipped). `detect_gpus()` is slow on first call (starts the GPU plugin) so the window calls it from `_HwProbe`; `speech_device()` only reads the cached result. Models: `ensure_model(models_dir, size, engine=…)` downloads CTranslate2 (`MODELS`) or OpenVINO int8 IR (`OV_MODELS`) files from Hugging Face with byte progress into `<models>/<size>` / `<models>/openvino/<size>`; the models folder is `app._models_dir()` (`%LOCALAPPDATA%` / `~/.cache`, **not** the roaming config dir). Audio is decoded by our ffmpeg (`load_audio`, 16 kHz f32le), so **PyAV is excluded from the build** and stubbed in `sys.modules` if missing. Chinese script is steered with `hotwords` (faster-whisper; every window sees them) / `initial_prompt` (OpenVINO). The voice filter (Silero VAD) drops singing over music, so an empty pass on loud audio is retried without it. **`import openvino` posts to Google Analytics** through `openvino_telemetry`; `captions.py` sets `sys.modules['openvino_telemetry'] = None` before anything imports it (OpenVINO then uses its own stub) and the spec excludes the package — `test_openvino_never_loads_its_telemetry` guards it. `--selftest` prints `captions=1 openvino=1` only if both engines really run in the packaged binary (OpenVINO: a tiny model saved and re-read as IR, compiled and run on the CPU plugin) and CI requires both; the spec copies each OpenVINO package's `libs/` folder whole minus unused frontends / NPU (`collect_dynamic_libs` missed the IR frontend).
**Fallbacks must never hang or crash** (each has a test): `detect_gpus(timeout)` runs the driver checks in a daemon thread and gives up (counts as no card, `gpus_checked()` True) instead of waiting on a stuck driver — the Auto captions dialog passes 3 s because it runs on the UI thread; `studio._run_with_progress(stall_s=…)` kills ffmpeg after `HW_STALL_S` without progress, used only for the graphics-card attempt so `compose_video` redoes it on the CPU; `app._stop_thread()` cancels and waits `_STOP_GRACE_MS`, and a thread that ignores it goes to `_STUCK` — **never destroy a running QThread** (Qt aborts), `main()` leaves with `os._exit` instead; `ensure_model` / `ensure_runtime` turn network and disk errors into friendly `RuntimeError`s and delete partial files (the CUDA download keeps a `.done` marker per package to resume). `_openvino_gpu` skips integrated GPUs under `MIN_IGPU_EUS` (64) execution units — a heuristic, not measured on old hardware.
- `vidgrab/cuda_runtime.py` — on-demand CUDA 12 libraries for NVIDIA cards: `ensure_runtime(models_dir)` downloads the pinned `nvidia-cublas-cu12` / `nvidia-cudnn-cu12` wheels (`PINS`: url + SHA-256, per platform; update by copying from PyPI), unpacks only the library files flat into `<models>/cuda`, then `register()`s them (`os.add_dll_directory` + `PATH` on Windows; `RTLD_GLOBAL` preload of cublasLt / cublas / cudnn on Linux, because CTranslate2 `dlopen`s `libcublas.so.12` / `cublas64_12.dll` by name). `libs_loadable()` probes the *main* libraries only — cuDNN's sub-libraries are loaded by cuDNN itself from its own folder. Unpacked it is 2 GB. Verified with the real wheels on Linux (cuBLAS / cuDNN load, cuDNN reports 9.27); not on an NVIDIA card.
- `vidgrab/gpu.py` — Qt-free hardware helpers: `detect_encoder(ffmpeg)` test-encodes with NVENC → Quick Sync → AMF and caches the first that works, `video_args()` gives the libx264 or hardware arguments for a quality preset (`studio.compose_video(hardware=True)` uses it and re-renders on the CPU if the card fails; filters stay on the CPU, only the encode moves); `speech_threads()` = performance cores (Windows `GetLogicalProcessorInformationEx` efficiency classes, Linux `/sys/devices/cpu_core`) capped at 8 — more threads on a hybrid CPU is several times *slower*. Settings `gpu_render` / `gpu_captions` (default on) gate them.
- `vidgrab/app.py` — the entire GUI: one `_QSS_TEMPLATE` rendered with `_PALETTES["dark"|"light"]` (`@TOKEN@` substitution) into `DARK_QSS`/`LIGHT_QSS`; `_Worker(QThread)` dispatches a named task (`probe`, `download`, `download_both`, `download_playlist`, `compose_video`, `compose_audio`) and relays results via Qt signals. Pages are indexed by `PAGE_DOWNLOAD/STUDIO/SETTINGS` (header text in `_PAGE_HEADERS`). The bottom log / progress / Download panel (`_bottom`) is shown only on the Download page.
- `vidgrab/jobs.py` — Qt-free `DownloadJob` + `run_job()`: one queued download, which is the media (`download` / `download_both` / `download_playlist`) plus optional captions (`downloader.fetch_subtitles`). Captions are retimed for trim/speed (`studio.retime_cues`) and either saved as `.srt` or burned in through `studio.compose_video`.
- `vidgrab/downloads_panel.py` — the Downloads list on the Download page: `DownloadItem` rows (queued / running / done / failed / cancelled) with Send to Studio, Cancel and Retry; finished items persist in `<config>/history.json`. The queue logic itself lives in `VidGrabWindow` (`_queue`, `_run_next_job`, `_dl_worker`): one job at a time, oldest first. Cancelling sets `_Worker.cancel()`, and the next progress callback raises `downloader.DownloadCancelled` (a yt-dlp `DownloadCancelled` subclass, so yt-dlp lets it through; the client-fallback loops re-raise it). There's no log in the UI: `_append_log` writes `<config>/vidgrab.log`.
- `vidgrab/studio_page.py` — `StudioPage`: toolbar, preview + Inspector (project / subtitle / music pages), and `TrackTimeline`. The timeline is painted, with **one row per clip** plus Subtitles and Music rows. Each clip block has start/end trim handles; the scale is frozen while dragging, and the dimmed "ghost" shows the rest of the source. Dragging a block vertically reorders; subtitle blocks move and resize. Thumbnails and waveforms come from `studio.thumbnail_png` / `studio.waveform`. It owns the project model (`_MediaClip` list + `SubtitleCue` list; selection is `("clip"|"cue", index)`). **Undo / redo** is snapshot-based: every edit calls `_record(kind)` *after* changing state; `_state()` is plain comparable data (clip paths + trims, cue tuples, music, style dict), probed media is cached by path in `_media` / `_music_media` so `_restore()` never re-probes, and same-`kind` edits within `COALESCE_S` merge (typing, sliders). New edit paths must call `_record()` or they won't be undoable. Per-clip **transitions** (`Clip.transition` / `transition_duration`, xfade names in `studio.TRANSITIONS`) overlap neighbouring clips by `studio.transition_overlaps()`, which both the renderer and the timeline (`TrackTimeline.overlaps()` / `offsets()`) use, so timeline times = output times; the main preview player switches at each transition's middle (`_segments()`), while a hidden second player (`StudioPreview.aux_player`, `_sync_transition()`) decodes the other clip and `VideoCanvas._paint_transition()` blends the latest frame of each file (`_last_frame`) like xfade. Both players must wait for `sourceChanged` before seeking: a stale "loaded" status from the previous file swallows the seek. With any overlap `build_video_command` joins pairwise (xfade + acrossfade, concat at cuts) and adds `settb=AVTB`, which xfade needs. **Framing** (`fit` / `zoom` / `pan_x` / `pan_y`) is `_frame_filter()` in ffmpeg and `preview.frame_geometry()` on the canvas — keep them in step. Timeline frames come from `ThumbCache` (QThreadPool + `thumbnail_png`, keyed by source time rounded to a `THUMB_STEPS` step); `StudioPage.shutdown()` must run before the window closes. Trim drags move a raw handle time incrementally (`_trim_move` / `_apply_trim`; Shift = ×0.1) and an edge timer keeps extending past the edge while squeezing `d["pps"]` / sliding `_view`. Background music is a list of `_Song`s (`_songs`; part start / end or None, timeline offset, volume, edge fade; only the last loops): a list of `BackgroundMusic` in the render (one `_music_bed()` each, all amixed with the clips) (atrim → aloop → atrim + asetpts → adelay → `asetpts=N/SR/TB`; adelay misreads aloop's timestamps and atrim/afade misread adelay's, so keep that order) and one `preview.MusicBed` + QMediaPlayer per song, kept in step by `StudioPreview._sync_music()`. **Images** are `studio.ImageOverlay`s (montage start / end, centre x / y and width as frame fractions, opacity, fade, rotation): looped stills overlaid with `enable=between(t,…)` before the subtitles (`_image_filter()`); the canvas draws / hit-tests them in their own rotated frame (`VideoCanvas._paint_images` / `_image_hit`). The Images and Subtitles rows share `TrackTimeline._lanes()`. **Per-clip speed** (`Clip.speed`, `studio.SPEED_RANGE`) is `setpts=(PTS-STARTPTS)/speed` + an `atempo` chain; durations in the graph use `_ResolvedClip.out_duration` (source part / speed), the timeline maps source time through `_MediaClip.kept()` and the preview through `preview.Segment.source_at()` / `montage_at()` + `setPlaybackRate`. **Subtitle effects**: `SubtitleCue.look` (overrides of the shared style; `studio.cue_style()`) becomes one ASS style per distinct look, and `animation` (`studio.ANIMATIONS`) becomes override tags in `format_ass`; `VideoCanvas._paint_cues` draws the same thing — keep them in step. Typewriter reveals with `\\1a/\\3a/\\4a` back to the style's own alphas, never `\\alpha&H00&` (that turns a see-through box opaque). **Multi-select** is `StudioPage._picked` (set of `(kind, index)`) plus the primary `_sel`; group drags and Ctrl+C/V/D go through it. **Guides** (`VideoCanvas._guides`, `SAFE`, `_snap_axis`) snap dragged subtitles / pictures to the centre and safe margins. **Export presets** (`EXPORT_PRESETS`) set resolution + suffix; `compose_video` renders a non-`.mp4` target (GIF, MP3) via a temp MP4 and `_export_args`. **Autosave** writes `<config>/studio-recovery.vgproj` every `AUTOSAVE_MS` while dirty; `app._offer_recovery()` offers it at start (not offscreen) and a clean close deletes it. Tests that call `new_project()` / `open_project()` with unsaved changes must patch `QMessageBox.question`, or the modal dialog hangs the run. The render goes through `app._Worker`, which must forward every `render_requested` key to `compose_video` (images were once dropped there; a test covers it). Headless (`offscreen`) runs never play sound. Projects (`.vgproj`, JSON) are written by `project_data()` and read by `open_project()`; paths are stored absolute + relative to the project file. `TrackTimeline` has its own zoom / horizontal view (`_zoom`, `_view`, `_x()` / `_t()`) rather than a horizontally scrolling widget, so the row headers stay put; drags record the playhead at press time (`head`) because selecting an item moves the playhead. It talks to the window only through a small host interface on `VidGrabWindow` (`t`, `icon`, `log`, `pick_*`, `ffmpeg_ok`, `default_output_dir`) and emits `render_requested(task, kwargs)`. Widgets register for re-translation via `_tr()`.
- `vidgrab/preview.py` — `StudioPreview`: one `QMediaPlayer` painted through a `QVideoSink` onto `VideoCanvas`, because QVideoWidget needs OpenGL, which WSLg and many Linux setups lack. It always previews the whole montage: it chains segments, switching source at each out-point, and overlays subtitles. While a trim handle moves, the page reloads the segments and seeks to the frame under the handle. Subtitles which can be dragged (`cue_moved` emits x/y fractions). The canvas converts libass font size (line height) to Qt pixel size (em) so the preview matches the render. An app-wide `_WheelGuard` event filter stops the mouse wheel from changing any QComboBox / spin box / slider (the wheel scrolls the parent instead). Avoid emoji in UI text: there is no emoji font on many systems, so icons are drawn with `_icon()`. Settings persist in `<config>/config.json`. `DEFAULT_SETTINGS` lists every key, and `_load_config()` merges the file over those defaults, so old files keep working. Use `win.setting(key)` / `win.set_setting(key, value)`; `_save_config(theme, lang, extra)` preserves keys it isn't given. Settings-page widgets register for re-translation with `_trw()`.
- `vidgrab/i18n.py` — `TRANS[lang][english_source_string]`; the English string *is* the key. `test_i18n.py` enforces that `zh` has exactly the English key set, so **any new or changed user-facing string must be added to both the `en` and `zh` tables**. Language switching re-applies text via `_apply_language()` / `retranslate()`.
- `vidgrab/network.py` — offline indicator probe. `vidgrab/icon.py` — programmatic icon drawing.
- `vidgrab/_version.py` — single source of truth for the version; `scripts/write_version_info.py` derives the Windows `version_info.txt` from it.

### Download pipeline gotchas (from history; don't regress)
- yt-dlp uses player client `tv_embedded` first (full resolution ladder), falling back to `android` (≤360p but reliable) when YouTube returns 403.
- Trims always download the full video then cut locally with ffmpeg — YouTube range requests (`download_sections`) 403 or silently return the full file.
- Intermediate files use temp suffixes (`.mp3tmp`, `.proctmp`, `.trimtmp`) and are renamed at the end, so MP3 extraction never clobbers an existing `.mp4` of the same title. `_locate_output()` finds the produced file by title/suffix.
- `find_ffmpeg()` search order: `sys._MEIPASS/ffmpeg/{win,linux}/…`, then `ffmpeg/` next to the exe, then PATH. Studio's `find_ffprobe()` looks beside ffmpeg first.

## Packaging & release

- `VidGrab.spec` embeds ffmpeg binaries from `ffmpeg/win/` or `ffmpeg/linux/` (legacy `ffmpeg/` fallback) plus `assets/` (icons, flags, NotoSans CJK fonts) and QtMultimedia. ffmpeg binaries are **never committed** — CI fails if any are tracked. **One ffmpeg version is pinned** in `ffmpeg/pin.json` (a BtbN month-end autobuild, kept long-term, with SHA-256s) and fetched by `scripts/fetch_ffmpeg.py` in every CI job, both builds, `scripts/build.ps1` and `make ffmpeg`; in development `find_ffmpeg()` already prefers `ffmpeg/<platform>/` and the Makefile puts `ffmpeg/linux` first on PATH. Upgrade by editing the pin, never by pointing a workflow at a "latest" URL.
- Lint + tests live in `.github/workflows/checks.yml`, called by both `ci.yml` and `release.yml` (a tag can't publish untested code); the live-YouTube integration job stays CI-only. Downloads retry over IPv4 after "Network is unreachable" (`downloader._try_clients`).
- Release = bump `vidgrab/_version.py`, add a `## <version>` section to `CHANGELOG.md`, then push a matching `v*` tag. `release.yml` fails on a tag/version mismatch, then builds both platforms and publishes `VidGrab-windows-x64.exe`, `VidGrab-linux-x64[.tar.xz]` and `SHA256SUMS.txt`. The notes come from that changelog section.
- The Linux binary is built on `ubuntu-22.04` on purpose (glibc floor); don't bump it to `ubuntu-latest`. Its runner needs PulseAudio/ALSA/xcb libs or QtMultimedia (inline preview) silently drops out; the `--selftest` step catches that.
- `fetch_subtitles` must request **exact** caption codes (`SUBTITLE_LANGS`). Wildcards such as `en-.*` also match YouTube's auto-translated tracks and trigger HTTP 429; `ignoreerrors` keeps the tracks that did download.
- Both build workflows run `tests/test_studio.py` against the ffmpeg they are about to embed (libass/amix/acrossfade must be present).
